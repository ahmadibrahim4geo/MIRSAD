MIRSAD Help Centre

Start here

MIRSAD Desktop is an independent Windows application for climate atlases from station locations, user points or a native regional climate grid. Outputs include Excel, GIS databases, rasters and PDF atlases. ArcGIS and a separate Python installation are not required. This manual describes implemented development version 0.4.0.dev8, rather than planned features.

  1. Select a geoprocessing tool.
  2. Configure Inputs → Climate → Raster → Outputs.
  3. Start with a small area, a complete period and Temperature/Precipitation to verify your inputs.
  4. Choose Run Tool; inspect task status, the output directory and manifest.json.

Export Points exports selected locations only; it does not download climate data or automatically create an atlas. Each tool keeps a separate working draft and point selection during the session. Store projects outside the application directory. Use a new project name for each run; existing projects are not silently overwritten.

Workspace and map

  • Tools and Contents: choose a tool and inspect layers, tables and outputs. A layer context menu offers zoom, table/properties and removal from the view. Removing a display layer does not delete its file.
  • Center tabs: Map, Attribute Table, Tasks, Input Info, About and PDF Atlas Preview. Use the tab bar arrows when space is limited.
  • Tool inspector: Inputs, Climate, Raster and Outputs. Drag splitters to resize panels; window geometry/layout are saved. The application menu can toggle panels or restore the layout.

Drag to pan; scroll or use +/− to zoom. Navigation controls also fit the data and show the world. The pin icon enables point placement: click the map and complete the point dialog, or press Esc to cancel. The coordinate readout is WGS84; tile display uses EPSG:3857, independently of analysis/output CRS.

The small layers icon opens the basemap panel: Esri imagery with/without labels, streets, topographic, light/dark gray, OpenStreetMap or no basemap. The panel identifies the current style and provider. Selecting a style, clicking outside, Close or Esc dismisses it; focus loss alone while taking a screenshot does not. Thumbnails illustrate styles and are not measurements or additional tile downloads.

Attribution remains below the map. New basemap tiles require internet; local points can be displayed without a basemap. A basemap does not select a climate provider. API-key Google/Azure basemaps are absent. Application chrome follows light/dark mode; the geographic map follows the selected basemap style.

Inputs, selection and coordinates

  1. Use Add Data / Ctrl+O for FileGDB, GeoPackage, Shapefile, GeoJSON, SQLite, GeoTIFF or Excel/CSV/TSV. Open a .gdb directory as a database and choose its layer.
  2. Choose the role: working points, polygon study boundary/clipping mask, or display context. Displayed lines/images do not automatically become climate input points.
  3. For tables, map ID, name, X and Y columns. X is longitude/easting; Y is latitude/northing. Excel point import reads the active worksheet; prepare unique headers without merged cells.
  4. Specify the actual CRS: WGS84 degrees are not UTM meters. Missing CRS must be assigned; stored CRS is read rather than silently redefined.
  5. Check the required points. Select Visible selects current filtered rows, not every station worldwide. Selection survives search, sorting and language changes.

To generate a point grid, load a polygon, set spacing in meters and generate. Reduce area or increase spacing to reduce point count. This grid differs from native NASA cells in Grid Raster. Review “Points inside boundary only” before running.

Keep identifiers as text with leading zeros. USAF alone is not unique: the catalogue retains WBAN, location and Station_Key. Source_Country is separate from display policy. Reference agreement/geographic QA is not field verification; country names do not trigger coordinate corrections.

Sources, coverage, resolution and sign-in

Auto is the default: choose the finest suitable product per variable within the selected provider and for the whole requested interval. Supported temperature, RH and dewpoint use ERA5-Land; other supported Open-Meteo variables use ERA5. Intervals beginning before 1950 use ERA5 throughout. Advanced settings allow a fixed manual model. Fixed-grid providers do not acquire fictional resolution choices. The UI previews the plan; Source_Resolution and raw records report the actual product. Smaller output pixels do not add source detail.

Need Sign In: CDS requires a personal API token and accepted dataset terms. IMERG requires NASA Earthdata username/password and GES DISC authorization. Enter your own credentials below the climate settings. Credentials stay in memory and pass to workers via stdin; they are absent from project, job and log files. Both adapters and conversion/protocol tests are implemented; live authenticated end-to-end access remains unverified.

Stations: NOAA GSOD requires USAF/WBAN/location. GHCN requires explicit GHCN_ID in an imported supporting station/point layer. No automatic identifier or nearest-station substitution is made. Gridded sources work at arbitrary points and station locations without becoming station observations.

Hybrid stages and gap filling

The sequence below is station Hybrid. Any-point Hybrid begins at ERA5; standalone runs only the selected source. All modules remain selectable; absent dependencies produce NULL with explicit quality status.

  1. Finish NOAA for every requested station/year first.
  2. Inventory missing station-variable-day cells, then finish the selected ERA5 model for the stations that need it.
  3. Use NASA POWER for remaining gaps; never replace valid higher-priority data.
  4. Aggregate complete days into months, apply selected monthly Gap Fill, then calculate indices.

Completed request checkpoints can be reused after cancellation or a rerun with the same settings. A missing NOAA file (404) differs from a connection failure; failed requests are retried on rerun. Raw values, quality flags and per-value sources remain available. NOAA records whose coordinates differ from the selected location by more than 0.05° are excluded with a reason, without moving the station.

MethodBehavior and limits
No FillKeep missing cells NULL.
Climatological Month MeanMean of the same calendar month across available years, falling back to the overall station mean under the current kernel. This is not necessarily the 1991–2020 baseline.
Linear + BoundaryInterpolate monthly values in time; boundary gaps can use the nearest available value. These are estimates.
Spatial IDWImplemented as network monthly completion in Hybrid: up to 3 original donor stations with inverse-distance weights. Donor keys/distances are recorded; inspect climate relevance when donors are distant. Estimated values are not reused as donors.

Temporal filling currently applies to mean-type variables; it does not automatically fill precipitation or wind direction. Explicit Hybrid spatial mode can estimate monthly rainfall, but not wind bearings. This spatial implementation also serves the new standalone NOAA/ERA5 paths after only the selected sources finish. Optional monthly estimates are recorded separately, never create daily observations and never fetch another provider. Select No Fill to retain missing months as NULL. Legacy NASA/Open-Meteo and regional paths retain separate monthly handling. Monthly estimates do not create daily observations or improve raw daily coverage. Read Gap_Filled_Months, monthly-estimates files and Status together; estimates are not station measurements.

Period, summaries and units

Set inclusive start/end dates as YYYY-MM-DD. Point downloads are daily and can cover partial periods; a complete scientific month requires every calendar day. A few days are not promoted into a full-month/year total. Partial-period fields such as R_Period_Total and T_Period_Mean differ from annual climate summaries. Coverage_Fraction measures availability, not accuracy.

Select Annual and required seasons; monthly fields remain in workbooks. Definitions are DJF=12/1/2, MAM=3/4/5, JJA=6/7/8 and SON=9/10/11. In an individual-year workbook, the current kernel groups December, January and February from that same exported calendar year, rather than previous December plus next January/February. Monthly interannual range compares the same month across years; it is not a single-day range.

Choose Metric/Imperial or individual temperature, precipitation, pressure, wind and solar units. Read Measurement_Unit and the Daily sheet's Unit: daily records use normalized source units and can differ from chosen summary units. Temperature differences and absolute temperatures have different Celsius/Fahrenheit conversions. Daily solar energy per area per day is not a W/m² power value unless explicitly identified as such.

Regional grid steps

  1. Select Grid Raster Climate Atlas.
  2. Choose the download AOI polygon/extent and an optional separate clipping study boundary; they serve different purposes.
  3. Request whole months, such as 2024-01-01 through 2024-12-31.
  4. Choose modules, units and output CRS. Choose NASA monthly, CHIRPS or CHELSA. The latter two enumerate original native cell centres inside the download polygon, capped at 20,000 cells. Their monthly rainfall totals are not multiplied by days.
  5. For rasters, select the full pipeline, metric processing CRS, cell size, interpolation and clipping mask; run.

Native source cells are read. Monthly precipitation rates are converted using the actual calendar month's length. Monthly data do not produce synthetic Daily observations. Different variable grids can leave dependencies missing at some coordinates; values are not fabricated to hide this. Regional requests are tiled, with limits of 512 tiles and 20,000 grid points; reduce the AOI if needed.

Rasters, CRS and classification

Spatial Reference Properties: Favorites holds systems you explicitly bookmark across sessions. Layers groups the actual source CRS of loaded spatial layers and lists the layers using each definition; undefined systems remain Unknown. Geographic Coordinate System uses the continent folders, and Projected Coordinate System retains the native Esri hierarchy. For example: UTM → WGS 1984 → Northern Hemisphere or Southern Hemisphere. UTM also contains continent, BLM and other groups from the Pro 3.6 reference. Search names, codes or folder names; clearing search restores previously expanded branches. Show selected reveals the selected path; Details exposes datum, units and projection parameters. Including additional Esri definitions never replaces this tree: definitions absent from the native snapshot use an explicitly separate branch because the public source does not declare their Pro folder paths. Selecting a layer CRS changes this choice, without rewriting its original dataset.

Implemented methods are IDW, Nearest, Linear TIN, Spline (thin plate), Ordinary Kriging (exponential). IDW exposes power and neighbour count; this does not mean every advanced ArcGIS Pro option has been migrated. Inspect point distribution, values and NULLs before interpolation. Use a study clipping mask; a rectangular raster extent is not an administrative boundary.

Output CRS can be a valid geographic/projected system. Spatial processing needs a projected CRS in meters and a meter-based cell size; EPSG:4326 degrees are not metric distance coordinates. Use a suitable local projection, such as an appropriate UTM zone for a small area. The CRS picker has Geographic/Projected trees, code/name search, the embedded ArcGIS Pro 3.6 taxonomy and a newer definitions option. A valid definition does not certify every datum transformation's accuracy or required grid availability.

Annual/seasonal field rasters, optional monthly rasters and a PDF atlas can be generated. Optional classification offers Jenks, Equal Interval or Quantile, with 2–16 requested classes. Classified rasters use class 1 for the highest values and 0 for NoData; fewer distinct values can reduce actual class count. Leave-one-out validation is not proof of field accuracy.

The default raster cap is one million cells; local Kriging is capped at 250,000. Increase cell size or reduce the study area if a resource limit appears. Smaller output cells do not add new observation detail. Specialized wind vectors/contours and some advanced spline, kriging and search options are not all implemented or numerically certified against ArcGIS.

Previews, tasks and cancellation

Open a specific result in the table tab, select its layer/worksheet and navigate pages. Previews are read-only and do not execute macros or alter workbooks. GeoTIFF/lines can be displayed as context layers; PDF pages appear in the atlas tab. A preview is not a working point input unless explicitly imported/selected for that role.

The task log shows download/export/raster progress, elapsed time and cancellation. Downloads, GIS and file inspection run outside the UI process. Cancellation may wait for an active network request; it does not mean the button was ignored. Keep partial results and use a new project name for a rerun. Hybrid can reuse completed request cache with identical settings.

Removing a view does not delete its source file. Keep the _internal directory with MIRSAD.exe; it is part of the application. Installation/uninstallation preserves user projects stored outside the application directory.

Worked workflows

A. A one-year station atlas

  1. Select the station tool, region/country and at least two required stations.
  2. Choose Hybrid, 2024-01-01 through 2024-12-31, Temperature and Precipitation.
  3. Start with the data workflow, new project name and output directory; run.
  4. Inspect Coverage and Raw_Data. Then enable the full pipeline, choose a suitable metric CRS, study mask and cell size for rasters.

B. Excel points in UTM

  1. Keep ID as text; prepare Name, Easting, Northing and a header row.
  2. Import and map X=Easting, Y=Northing and the correct UTM CRS; do not assign WGS84 merely because the map displays it.
  3. Select points. Choose NASA/Open-Meteo to download, or existing numeric attributes for interpolation without downloading.

C. A NASA regional grid atlas

  1. Select Grid Raster and a small download AOI plus study mask.
  2. Request a whole month, such as 2024-01-01 through 2024-01-31.
  3. Select modules, enable the full pipeline if needed, run and inspect native cells/gaps. No Daily records are expected.

Install and run

MIRSAD Desktop is an independent 64-bit Windows application. Use the approved installer when an approved release is available, or the complete development folder. Keep _internal beside MIRSAD.exe; the EXE alone is incomplete. Store projects outside the application directory.

Add the three .pyt files to the ArcGIS Pro or ArcMap Catalog, keeping utils and repository dependencies beside them. ArcGIS spatial operations require the appropriate Spatial Analyst licence. Desktop does not require ArcGIS.

MIRSAD.exe --user-guide --language en --help-topic tool-points opens help alone. Without Desktop, open Help/index.html for offline contents, search, bookmarks and printing.

Help in Pro and ArcMap

Add Point, Weather Stations and Grid Raster toolboxes separately. Use Item Description/View Help to read a tool summary and follow the full local manual. Toolbox/tool XML metadata are associated by filename and travel with the .pyt files.

The legacy runtime supports ArcMap Python 2.7 and Pro Python 3. Help requires no Qt installation in ArcGIS Python: use local HTML or launch Desktop help in a separate process. From toolbox Python: from utils.help_viewer import open_help; open_help("tool-stations", "en").

Native verification is recorded for Pro 3.6. Native ArcMap acceptance remained unconfirmed in dev7; Python 2.7 tests are separate evidence. Remaining output-schema and advanced-raster differences are documented.

From source record to exported field

  1. Read the selected source and preserve identifiers, time, location, units, missing flags and provenance. Source response names can differ from the normalized variable codes above; a Daily sheet may use a long or wide layout.
  2. Decode missing sentinels to NULL, normalize units and aggregate to monthly input. Daily precipitation needs a complete calendar month before summing. The legacy daily path can average available non-rain days, whereas Desktop daily monthly assembly requires complete months. Native monthly/composite products retain their actual support; they do not fabricate daily observations.
  3. For Hybrid, complete station download first, then fill only eligible missing source cells from the secondary source. Monthly gap filling, if selected, is a later separate stage. Consult the Hybrid page for its provenance and policies.
  4. Compute C_m(X) for each calendar month, then evaluate the selected element's formula. Nonlinear indices evaluated on monthly means are not equivalent to means of daily indices.
  5. Apply host coverage guards and output filters, then display-unit conversion and rounding. Exported columns contain values, not Excel formulas. The same calculated record feeds spatial and tabular exports in that host.

Periods and missing data

Annual means in the generic kernel average valid climatological months without weighting month length. Annual range means the largest minus smallest climatological month. An optional January_Range means the spread of January values between at least two years; it is a different statistic. Rainfall and PET annual totals require all 12 months, seasonal totals require all three. DJF means December, January and February associated with the same year key; it does not move December to the previous winter year. MAM, JJA and SON use 3–5, 6–8 and 9–11; these names are fixed, including in the Southern Hemisphere.

Desktop guards annual output when no complete dependency year exists. Direct daily Temperature/Precipitation summaries also use their complete-period summary path; Hybrid/native-monthly routes retain kernel aggregation with the coverage guards. Thus shared equations alone do not guarantee identical aggregates with different gaps or input routes. T_Period_Mean averages valid daily observations; R_Period_Total is only reported for a complete requested daily period. Coverage and source flags must accompany interpretation. Missing precipitation is never silently zero.

Keep map titles concise, for example “Mean precipitation”, with the period and unit in the title or legend. A climatic mean can average accumulations: R_Annual_Mean averages complete annual totals, and R_Summer_Mean averages summer totals. Both are means, rather than means of daily rainfall. Put the aggregation steps in the methodology instead of expanding the map title into the entire calculation. ET_Annual_Mean carries PET summed from climatological months, as its element table explains. Use each field table to identify the operation and unit while retaining existing map titles and field names. Optional ranges and extended HI/WC fields are not enabled in every export.

Unit conversion and calculation limits

Derived indices are calculated in their prescribed internal units before output conversion. Changing a display unit must not put Fahrenheit into P<2T or inches into De Martonne. A range, anomaly, slope or temperature difference is a delta, not an absolute temperature.

Recorded implementation difference: LST minus air temperature

The legacy toolbox converter recognizes delta names containing Range, Trend, Anom or Diff. LST_minus_T_* does not match that rule: its Fahrenheit/Kelvin conversion currently adds the absolute offset incorrectly. Desktop explicitly corrects these LST difference fields after conversion. For consistent interpretation of this difference between the hosts, use Celsius until the legacy converter is separately corrected and verified. This documentation change does not silently change calculations or old output files.

Reading rounded columns

Calculations generally use unrounded internal inputs and then round output fields. The documented monthly LST difference is an exception using rounded monthly temperature columns; summary-of-monthly trend fields also average their already rounded monthly results. Rainfall totals may not reproduce a derived aridity ratio by dividing rounded exported columns, especially with unequal year coverage. Keep raw inputs and coverage information.

Method references and implementation scope

FAO-56: radiation and meteorological calculations; NOAA/WPC: Rothfusz heat index; NWS: wind chill; Stull (2011): wet-bulb approximation. These describe methods, not a claim that every standard or validity guard is fully implemented. The equation pages state the actual repository behavior reviewed on 18 October 2026.

The generic mean kernel skips missing months and can return a partial-month aggregate. Desktop applies a complete-year guard to annual fields, and direct daily Temperature can replace summaries with means of complete years/seasons. See calculation flow for these differences.
