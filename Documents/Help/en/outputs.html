Desktop Daily is a long table: Station_Key, Station_ID, Station_Name, Date, Variable, Unit, Value. Do not assume Toolbox's wide-table layout. English field names remain stable while UI labels are localized. Read Status, Error_Msg, Coverage_Fraction and Valid_Days/Expected_Days or Valid_Months/Expected_Months. NULL means missing, not zero.

Complete means requested outputs passed their checks. Partial means saved results coexist with gaps/failed stages; inspect the log. NO_DATA describes absent source data and can coexist with documented monthly estimates, so read Gap Fill fields too. INSUFFICIENT_HISTORY concerns scientific record length. A successful GeoPackage does not hide a failed GDB; tables can succeed when rasters fail. Excel is the normal tabular format; inspect any explicitly reported CSV fallback.

Desktop identity, coverage and Daily row dictionary

In Data and Month, each row is a point or station record; climate columns hold the statistics explained in the field-name guide and element pages. Individual-year exports refer to that year. Source_Data describes sources and coverage; do not assume each row is an independent daily observation. Toolbox identity fields and column order can differ; preserve original keys and do not join by row number.

ColumnMeaning and interpretation
Station_Key / Station_ID / WBAN / Station_NameStable record key / USAF station or point identifier / WBAN identifier / name. Identifiers are text and retain leading zeros; Station_ID alone is not a sufficient unique station key.
Point_Lat / Point_Lon / Elevation_mGeographic latitude and longitude in WGS 84 degrees, and elevation in metres. These attributes need not equal projected layer geometry coordinates.
Country / Source_Country / Coordinate_QADisplay country / original source country code / coordinate audit status. Catalogue agreement is not field verification.
Point_Type / Input_Source / SourcePoint type / input location source / climate data source. Location provenance can differ from the climate provider.
Data_Start / Data_End / Measurement_UnitRecorded run period boundaries and element unit; boundaries do not prove complete daily coverage. Read each field’s own unit, especially speed versus direction or daily mean versus total energy.
Valid_Days / Expected_DaysDays with valid required element inputs / requested days inclusive of start and end, for the daily path. These are not station counts.
Valid_Months / Expected_MonthsMonths with full required-input and quality coverage / requested months in the native monthly path. Daily counters are NULL on this path.
Coverage_FractionA fraction from 0 to 1, not 0 to 100: daily valid days / requested days; native monthly mean of requested-month coverage fractions, taking the weakest required input within each month. For example, 0.8 means 80%.
Status / Error_MsgPoint-and-element record status and explanation of missing data or failure. A populated climate value alone does not establish completeness. Record status differs from project completion in the manifest.
Gap_Fill_Method / Source_Temporal_ResolutionRecorded gap-filling method / original temporal resolution, such as monthly or composite. A monthly estimate is not an original observed day.
T_Period_Mean / R_Period_TotalMean valid daily air temperatures within the requested period / precipitation sum only when the requested daily period is complete. That period can be shorter than a year; these do not automatically replace annual climatological means.
Date / Variable / Unit / ValueIn Daily: day / variable code / this value’s unit / value. For example, T2M with value 20 and unit °C describes this point on that day, not its annual mean. A point appearing on different days or for different variables is expected.
