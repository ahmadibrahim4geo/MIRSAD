# مرصاد | MIRSAD Desktop

نسخة تطوير 0.4 لنظام Windows، بمساحة عمل جغرافية عربية/إنجليزية، ووضع فاتح/داكن وشعار مرصاد المعتمد.

## التشغيل — مكانان ثابتان فقط

- التطوير: `runtime/development/MIRSAD.exe`.
- الإصدار المعتمد: `runtime/stable/MIRSAD.exe`؛ محجوز حتى اعتماد أول نسخة.

افتح ملف EXE من مجلد التطوير. مجلد `_internal` بجانبه جزء من نفس التطبيق ويجب أن يبقى معه. لا يحتاج تشغيله تثبيت Python أو ArcGIS أو وجود ملفات Toolbox. لا تنقل EXE وحده عند نقل البرنامج إلى جهاز آخر؛ انقل مجلد القناة كاملًا.

## الأمان والثبات

تُعزل قراءة ومعالجة GIS عن عملية الواجهة، مع حدود للمدخلات والذاكرة المتوقعة وأحجام الاستجابة وتوسعة Excel، ورفض الروابط وأنواع الملفات غير المدعومة، وعدم تشغيل صيغ Excel من المدخلات. يسجل `.mirsad-jobs` حالات العمل والأخطاء، ولا يرفع تقارير تلقائيًا. فحص 38 حزمة بتاريخ 17 أكتوبر 2026 لم يجد ثغرات معروفة؛ هذا ليس ضمانًا بانعدام ثغرات التطبيق أو المكتبات الأصلية. التفاصيل في `docs/SECURITY.md`.

خصائص EXE تحمل Ahmad Ibrahim وMIRSAD Desktop. لا توجد شهادة توقيع موثوقة متاحة حاليًا؛ لذلك لا نزعم إزالة رسالة Windows «ناشر غير معروف». برنامج التوقيع المنفصل يقبل شهادة يحددها المطور، ولا يغير إعدادات أمان Windows.

## التطوير

البيئة `.venv` خاصة بـDesktop؛ لا تستخدم ArcGIS Python للتجميع. التبعيات المثبتة موثقة في `requirements.lock`، ويشمل التوزيع إشعارات تراخيص الأطراف الثالثة.

```powershell
& '.\scripts\build_development.ps1'
```

الأمر يجهز الموارد، يختبر الكود، يبني في `.build`، يختبر EXE نفسه من مجلد عمل خارج المستودع، ثم يستبدل مسار التطوير الثابت. لا ينشئ تطبيقات مرقمة. ملفات الاختبارات في `.test-output` فقط.

## الترقية بعد الموافقة

بعد مراجعة المستخدم للنسخة، يُستخدم **bundle_sha256** من `runtime/development/build_manifest.json`:

```powershell
& '.\.venv\Scripts\python.exe' scripts/promote_stable.py --approved-sha256 '<approved bundle hash>'
```

لا تُنفذ الترقية قبل الموافقة. يتحقق السكربت من كامل حزمة المرشح ويعيد الاختبار، ثم يبدل قناة النسخة النهائية مع استرجاعها عند فشل تبديل المجلد. لا تدخل مشروعات المستخدم في هذه العملية.
