# خطة مركز مساعدة مرصاد وتجهيز المستودع للمساهمات

التاريخ: 18 أكتوبر 2026؛ تحديث التنفيذ: 19 أكتوبر 2026. الحالة: **قبول dev8 محليًا وclone نظيف اكتمل؛ الأدلة والحدود الحالية في [تقرير التنفيذ](../MIRSAD%20Desktop/docs/DEV8_HELP_AND_REPOSITORY.md)**.

الهدف: دليل عربي/إنجليزي احترافي، يعمل دون إنترنت، يخدم أدوات ArcGIS Pro وArcMap وMIRSAD Desktop من مصدر محتوى واحد، ثم تنظيم المشروع وتجهيز مساهمة المطورين من نسخة مستودع نظيفة قابلة للبناء.

## 1. القرار المقترح

الصورة المرجعية تشبه عارض Windows HTML Help لملفات CHM. لا يمكن تحديد امتداد الملف من الصورة وحدها. الفكرة المعتمدة في هذه الخطة هي تجربة الاستخدام: شجرة محتويات، وبحث، ومفضلة، وصفحة شرح، وأزرار تنقل وطباعة.

التنفيذ الأساسي المقترح: تطوير عارض Qt الحالي داخل Desktop، مع وضع يفتح الدليل وحده عبر نفس EXE، وتوليد دليل HTML مستقل للأدوات والموقع. لا ننشئ تطبيقًا موازيًا أو مسار تشغيل ثالثًا. CHM مخرج مطلوب بتوجيه صاحب المشروع اللاحق؛ يولد بالعربية والإنجليزية من المحتوى نفسه مع فهرس بحث كامل، ويفحص داخل Windows بجانب Qt وHTML.

| الاستخدام | طريقة فتح الدليل المقترحة |
|---|---|
| Help أو F1 داخل Desktop | نافذة مساعدة مستقلة غير حاجبة للعمل، تصل مباشرة إلى موضوع الأداة/الحقل النشط |
| فتح الدليل وحده | وضع مخصص في `MIRSAD.exe` يفتح مركز المساعدة دون مساحة الخريطة أو تشغيل تنزيل/حساب |
| ArcGIS Pro وArcMap | شرح مختصر داخل مساعدة Esri الأصلية، وروابط مباشرة إلى موضوع الأداة في حزمة HTML المحلية؛ يمكن فتح عارض Desktop خارجيًا إذا كان مثبتًا |
| Toolbox دون Desktop | حزمة HTML كاملة مستقلة، بلا تثبيت Qt أو استيراده في عملية ArcGIS وبلا خادم محلي مطلوب |
| الموقع والمستودع | نفس الموضوعات وروابطها المستقرة، بتصميم متجاوب وإصدار واضح |

لا يُفترض أن زر مساعدة Esri الأصلي يمكن استبداله مباشرة بنافذة Qt. يجري اختبار نقاط الربط المدعومة في كل مضيف. تبقى وظائف المعالجة وأسماء الأدوات ومعاملاتها كما هي.

## 2. خط الأساس الذي فُحص

- العارض الحالي `MIRSAD Desktop/src/mirsad_desktop/userguide.py` نافذة Qt غير حاجبة، بفهرس مسطّح من 15 فصلًا، وبحث داخل النص، ولغتين وثيم متوافق مع البرنامج.
- `MIRSAD Desktop/scripts/build_user_guide.py` يولد HTML وفهرسًا مضمنًا. المحتوى الكبير داخل سكربت التوليد يحتاج فصلًا إلى موضوعات يسهل تحريرها ومراجعتها.
- سجل المصادر المشترك `data/climate_sources.json` والسجل العلمي المضمن موجودان؛ نعيد استخدامهما بدل كتابة جداول مصادر ودقات منفصلة يدويًا.
- لوحظ وصف مختصر للأداة الإقليمية يذكر NASA وحدها رغم إضافة CHIRPS/CHELSA؛ مراجعة التناقضات بين الملخصات والفصول جزء من التنفيذ.
- فرع Desktop ظاهر حاليًا كملفات غير متعقبة في Git، بينما قناة التطوير مبنية محليًا. وجود EXE محلي لا يثبت أن مطورًا آخر يستطيع بناءه بعد clone.
- توجد ملفات مؤقتة في الجذر: `pip-build-tracker-*` و`pip-ephem-wheel-cache-*` و`pip-install-*`، ومجلدات تجارب مثل `DepthTest_TMP` و`ElementTest_TMP` و`ProvTest_TMP` و`SigTest_TMP` و`TolFocal_TMP`، وملف `hello.spec`. هذه **مرشحات فحص**، وليست قائمة حذف معتمدة.
- لا توجد ملفات محلية ظاهرة للمساهمة أو سياسة الأمن أو قوالب المجتمع أو مسارات CI ضمن `.github/`. الرخصة MIT والهوية المعتمدة موجودتان.
- اكتشاف كل اختبارات الجذر معًا ليس ناجحًا حاليًا: اختبارات ArcPy الأصلية تختلط ببدائل ArcPy وتوقعات تاريخية. الاختبارات ذات الصلة اجتازت تشغيلًا منفصلًا. تفاصيل الحالة في `MIRSAD Desktop/docs/DEV7_SOURCE_ACCEPTANCE.md`.
- توجد تعديلات وحذوفات سابقة في Sample Data وقواعد البيانات وXML؛ تحفظ كما هي ولا تُضم إلى تنظيف أو commit عرضي.

## 3. شكل مركز المساعدة

1. نافذة بعنوان «مركز مساعدة مرصاد / MIRSAD Help»، بالشعار وبيانات المطور المعتمدة، وقابلة للتكبير والتصغير وتغيير الحجم.
2. شريط أدوات: رجوع، تقدم، الرئيسية، طباعة الموضوع، إخفاء/إظهار الفهرس، حجم النص، اللغة، والثيم.
3. لوحة جانبية بتبويبات Contents وSearch وFavorites، وشجرة قابلة للطي بدل عرض كل التفاصيل دفعة واحدة. تظهر يمينًا للعربية ويسارًا للإنجليزية.
4. صفحة موضوع واحدة في كل مرة، بعنوان واضح، ومسار تنقل، وروابط «موضوع مرتبط» و«السابق/التالي»، وصور من الإصدار الفعلي.
5. البحث يعرض قائمة نتائج بعناوين ومقتطفات ويميز التطابق داخل الموضوع. يشمل كامل الدليل، ويدعم العربية والمصطلحات الإنجليزية وأكواد المعاملات؛ لا يغير النص الأصلي عند تطبيع البحث.
6. المفضلة تحفظ معرف الموضوع واللغة محليًا، مع آخر موضوع وحجم النص وأبعاد النافذة. لا تحفظ إعدادات التحليل أو بيانات الدخول ضمن إعدادات الدليل.
7. تبديل اللغة يحتفظ بالموضوع المقابل عبر معرف ثابت؛ وتظهر الجداول والأكواد المختلطة الاتجاه بصورة سليمة.
8. الطباعة ومعاينة الطباعة/PDF تحافظان على العربية والجداول والصور، وتستخدمان خلفية ورقية مقروءة مستقلة عن الثيم الداكن.
9. الموارد محلية، والروابط الخارجية واضحة وتفتح عند اختيار المستخدم. لا تشغيل أكواد أو تنزيل بيانات أو اتصال بحساب من عرض صفحة شرح.

## 4. تنظيم المحتوى

المستوى الأول: «ابدأ هنا»، «التثبيت والتشغيل»، «أدوات ArcGIS»، «MIRSAD Desktop»، «المصادر والنماذج»، «المنهجية العلمية»، «المخرجات»، «حل المشكلات»، «المساهمة والتطوير».

تحت أدوات ArcGIS توجد الأدوات الثلاث: Point Climate Atlas، Weather Stations Climate Atlas، Grid Raster Climate Atlas. لكل أداة صفحة عامة وصفحات للمدخلات والمناخ والمساقط والراستر والمخرجات، مع توضيح الفروق الفعلية بين Pro وArcMap وDesktop.

لكل معامل: الاسم الفعلي، الغرض، نوع البيانات، المطلوب/الاختياري، القيمة الافتراضية، الوحدات، متى يتاح أو يتعطل، القيود، مثال، والرسائل المحتملة وكيفية التعامل معها.

لكل مصدر: المنتج، العناصر، التغطية الجغرافية والزمنية، الدقة الأصلية لكل عنصر، تأخر النشر، شروط الحساب، خطوات إعداد المستخدم لحسابه، الجودة، والتوثيق الرسمي. تعرض حدود التحقق بوضوح، خصوصًا CDS وIMERG، ولا تدرج أي أسرار حقيقية في الصور أو الأمثلة.

لكل نموذج علمي: المدخلات والتبعيات والوحدات والتجميع الزمني وقاعدة الفقد والتغطية ومثال محسوب. يشرح الهجين NOAA ثم ERA5 ثم NASA ثم Gap Fill الشهري، مع الفرق بين الرصد والتقدير.

أمثلة عملية منفصلة: نقاط المستخدم، محطات، منطقة دراسة وراستر، بيانات موجودة دون تنزيل، اختيار CRS، استعادة عمل ملغى، وفهم النجاح الجزئي. توثق المخرجات المتاحة فعلًا والفروق المتبقية، دون وصفها كتطابق مكتمل.

## 5. مصدر واحد للمحتوى وبناء قابل للتكرار

المسارات المقترحة الجديدة تحت `Documents/Help/`: مجلدا `ar/` و`en/` للموضوعات، و`media/` للصور المعتمدة، وملف فهرس يربط معرفات الموضوعات وترتيبها ومعرفات الأدوات والمعاملات.

- نقل المحتوى يدويًا على مراحل من المولد الحالي، مع الاحتفاظ بروابط الفصول السابقة أو تحويلها إلى معرفاتها المقابلة. لا نقل جماعي لكل Documents ولا كسر روابط الموقع.
- بيانات المصادر تأتي من السجل المشترك، والعناصر من registry، والمعاملات من لقطة متحققة لأسماء الأدوات الفعلية. لا تستورد أدوات ArcPy لتنفيذها أثناء بناء الوثائق في CI العام.
- مولد واحد ينتج صفحات HTML وفهرس البحث والنسخة المضمنة؛ يضمّن Desktop موارده داخل حزمته دون الاعتماد على Documents أو مجلد Toolbox عند التشغيل.
- الدليل المستقل يضم ملفات المحتوى والموارد اللازمة. البحث والطباعة والروابط تعمل من `file://` دون CDN أو `fetch` يحتاج خادمًا.
- مساعدة Esri الأصلية مختصرة ومتصلة بالموضوع الكامل. تراجع ملفات `.pyt.xml` حسب ارتباطها بالأداة؛ لا تزال XML بحجة أنها مولدة، ولا يستبدل تعديل ArcGIS غير المرتبط بالمهمة.
- يتحقق البناء من تطابق معرفات اللغتين، وعدم تكرارها، وسلامة الصور والروابط، ومنع ذكر مصدر مخطط على أنه منفذ.

## 6. تنظيف المشروع والاختبارات

يبدأ التنفيذ بتقرير جرد يحوي المسار والحجم والتعقب في Git والغرض والجهة التي تولده والمراجع إليه والإجراء المقترح. لا يكفي الاسم «قديم» أو نتيجة اختبار فاشلة للحذف.

| الصنف | الإجراء |
|---|---|
| كاش Python وpip ومخرجات بناء متروكة | التأكد من عدم استخدامها في عملية قائمة، ومن وقوع المسار داخل المشروع، ثم حذف المؤقت المؤكد وتحديث قواعد التجاهل المحددة |
| `.venv` و`.build` و`.test-output` | تبقى محلية ومعزولة عن Git؛ توثق إعادة إنشائها. تحفظ تقارير قبول مختصرة وصور مرجعية لازمة قبل أي تقليص للمخرجات الضخمة |
| `hello.spec` وتجارب الجذر | فحص الاستدعاءات والمحتوى؛ إزالة التجربة التي ثبت عدم استخدامها، أو نقل المصدر المفيد بمراجع محدثة |
| اختبارات صحيحة تكشف عطلًا | إصلاح السبب مع إبقاء الاختبار والتغطية |
| اختبارات بعقود تاريخية | مقارنة مطلبها بالعقد الحالي؛ تحديث مبرر أو دمج تكرارها، مع سجل يوضح التغطية البديلة |
| اختبارات تتطلب ArcGIS | تصنيف native وبيئة/ترخيص واضحين؛ عدم عرض عدم توفر المضيف على أنه نجاح أو خطأ علمي |
| اختبارات بدائل ArcPy | عزلها في عمليات أو fixtures تستعيد الحالة؛ منع تلوث `sys.modules` لباقي الاختبارات |
| بيانات المستخدم وSample Data وGDB وXML | الحفاظ عليها وعلى حذوفاتها السابقة؛ لا تنظيف عام أو استعادة أو إضافة عرضية لها |
| كتالوج المحطات والمراجع والهوية | أصول تحقق لازمة وليست كاشًا؛ تبقى مع الإصدار والبصمات والمصدر والترخيص |
| أدلة قديمة مفيدة | فهرسة أو أرشفة واضحة بعد مراجعة الروابط؛ لا نسخ متعددة متعارضة توحي بأنها الدليل الحالي |

تنتج مصفوفة اختبارات توضح Python 2.7 وPython 3 وDesktop وnative Pro وnative ArcMap، وأمر التشغيل الصحيح والاعتماديات والحالة. يظل معيار النجاح رقميًا/تعاقديًا؛ لا تخفف اختبارات المطر وNULL والوحدات أو تستبدل التحقق الأصلي بمحاكاة.

## 7. تجهيز المستودع للمساهمين

- الإبقاء على المستودع الحالي `ahmadibrahim4geo/MIRSAD` وDesktop داخل `MIRSAD Desktop/`؛ لا حاجة إلى تقسيمه الآن إلى مستودعات جديدة.
- تحديث README الرئيسي ليعرض الأدوات وDesktop وحالة التطوير واللقطات والحدود ودليل الاستخدام، مع فصل تعليمات المستخدم عن إعداد المطور.
- إضافة CONTRIBUTING بالعربية والإنجليزية، وشرح الفروع وPull Requests وتشغيل الاختبارات وتعديل الدليل وإضافة مصدر/عنصر علمي. البداية المناسبة للمساهم الجديد موضوعات صغيرة ذات معيار قبول واضح.
- إضافة SECURITY وCODE_OF_CONDUCT وSUPPORT، وقوالب Bug وFeature وDocumentation وPR، مع الحفاظ على بيانات المطور والرخصة الحالية. لا ينشأ اتصال أو بريد دعم جديد غير معتمد.
- توثيق المعمارية والتبعيات وتوليد science والكتالوج والأصول والأدلة. تثبت عملية clean clone أن الملفات الضرورية متعقبة، ومنها لقطة المحطات ومراجعها، ولا تعتمد على ملفات محلية متجاهلة أو مسارات جهاز المطور.
- تنظيم CI لفحوص الروابط والوثائق والاختبارات المشتركة وDesktop، مع عزل اختبارات ArcPy. Pro وArcMap يحتاجان بيئة مرخصة مناسبة؛ لا يدعى تشغيلهما على عامل عام غير مزود بهما. فحوص الشبكة/الحسابات منفصلة عن الاختبارات الحتمية.
- مراجعة التراخيص وإشعارات التبعيات والملفات الكبيرة والمسارات المحلية والبيانات الحساسة قبل النشر، دون طباعة الأسرار. مراجعة حجم الملفات قبل اختيار Git LFS؛ لا إضافته تلقائيًا لكل ملف ثنائي.
- تفصل تغييرات الدليل والتنظيم/الاختبارات وملفات المساهمة إلى commits قابلة للمراجعة، دون إضافة التغييرات السابقة في بيانات المستخدم عرضيًا.
- يرفع كود المصدر والتوثيق والأصول اللازمة. EXE ومجلد `_internal` والمثبت والكاش والبيئة الافتراضية لا تدخل تاريخ Git؛ توزع حزمة البرنامج كاملة عبر قناة إصدار مناسبة بعد اعتماد المرشح. لا يرفع EXE منفردًا غير قابل للتشغيل.
- تحديث الكود في المستودع منفصل عن ترقية stable أو نشر Release: يبقى المرشح موسومًا بوضوح كنسخة تطوير وحدودها حتى اعتماده. تهيأ المناقشات والأفكار للمساهمين عند مرحلة نشر إعدادات المستودع.

## 9. التحقق المطلوب

- العربية والإنجليزية وRTL/LTR، الوضعان، التنقل بلوحة المفاتيح وقارئ الشاشة، وحالات التركيز والتباين، وWindows scaling عند 100% و125% و150% و200%.
- البحث بالعربية وبأسماء العناصر/المصادر والمعاملات الإنجليزية، والنتائج الفارغة، والرجوع/التقدم، والمفضلة بعد إعادة التشغيل، والطباعة دون قص الجداول.
- تشغيل الدليل كله دون إنترنت، بما فيه البحث والصور والروابط الداخلية، وفتح حزمة HTML محليًا، ومسارات تحتوي مسافات وعربية.
- اختبار Help/F1 من الأدوات وصفحات الإعدادات. فتح الشرح لا يغير مسودة أو بيانات أو ملفات مخرجات.
- اختبار EXE المعبأ من خارج المستودع، ووضع الدليل وحده دون تحميل خريطة/إجراء طلبات مناخية، ومساعدة الأدوات في البيئتين الأصليتين مع تسجيل حدود أي تحقق متعذر.
